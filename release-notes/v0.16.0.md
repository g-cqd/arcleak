# arcleak 0.16.0 (from 0.15.1)

arcleak reads more of the ways a closure or a token is kept alive, and reports fewer shapes that do not leak. The pins are
those of 0.15.1: analyzerkit `d76118d`, AemiJSON `cbac433`, AemiProtobuf `7393728`, aemi `0ef4279`, AemiRegex `bc59772`.
On the reference app, ask, Atelier and the other g-cqd corpora the findings are the same as 0.15.1's (the reference app: 4, Atelier: 1,
the rest: 0); the changes below show in code written the way the new fixtures are.

## Findings that may appear

- A closure that captures `self` and is stored through a subscript (`handlers[key] = { … }`, `updateValue`), through `+=` of
  closure literals, or on either side of a conditional (`cond ? { … } : { … }`). Storage used to be named only as `member` or
  `self.member`.
- A token (a `sink`, an observation) handed to `append` or `insert` of a collection that `self` stores, or stored at a
  subscript of one, is owned by `self` like a `.store(in:)` is. A local collection still dies at scope end and is not
  reported.
- A dispatch source configured as a local and then stored on `self`.
- A `Task` whose loop ends only on cancellation (`while !Task.isCancelled`) is a non-terminating body like `while true`: it keeps
  `self`, so a `cancel()` in `deinit` never runs. A reachable `cancel()`, a `[weak self]` capture or a second loop condition keep
  it silent.

## Findings that may disappear

- `Timer(timeInterval:target:selector:…)` and `Timer(timeInterval:repeats:block:)`: until they are added to a run loop they do not
  retain their target.
- `[1, 2].publisher` and `(0..<3).publisher`: a publisher over a literal sequence is finite and completes.
- A `for` loop variable, a `case` binding or a closure parameter that has the name of a method of the type: it is the binding,
  not a bound method reference to `self`. Only `let`/`var` locals and parameters shadowed methods before.
