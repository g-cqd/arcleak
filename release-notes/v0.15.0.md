# arcleak 0.15.0 (from 0.14.0)

One new rule, `continuation-overwrite` (analyzerkit roadmap 0065), moved here from modeler before modeler released it:
a dropped continuation is a leaked caller, the lifetime arcleak is about. analyzerkit is still `0a13bbf`.

## Report

The new rule id, `continuation-overwrite`, in reports, SARIF's rule catalogue, `arcleak rules` and `arcleak explain`.

## Configuration

`continuation-overwrite` can be disabled or given another severity like any rule. Default: warning, since the leak
needs two calls that overlap.

## Cache

The facts gain a kind of API call, `continuationStore`; a cache written by 0.14.0 is not reused (the build identity
changes with the version).

## Findings that may appear

`continuation-overwrite`: `member = continuation` as a top-level statement of a `with(Checked|Unsafe)(Throwing)?
Continuation` closure whose member is a stored property, when the closure and the enclosing method hold no condition
before the store and nothing before it mentions the member. A second call before the first one's resume replaces the
first caller's continuation, which then never resumes. A `guard`, an `if` or any other condition before the store (it
may be how the code keeps a second call out), a continuation kept under a key or appended, a store on one branch and a
computed member stay silent: ten such shapes are in the clean fixtures.

On maintastic (develop, its `.arcleak.json` and Xcode index): one, `Camera.getCurrentFrameInHD()`, which five call
sites can overlap. On the family's repositories: none.
