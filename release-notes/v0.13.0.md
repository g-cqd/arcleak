# arcleak 0.13.0 (from 0.12.1)

Wave 1 of the analyzer release train (analyzerkit tag `analyzerkit-wave-1`): arcleak on analyzerkit's shared
foundations. Without an index store, findings are identical to 0.12.1 on maintastic, analyzerkit and the g-cqd
packages.

## Flags

- Added: `--exclude-path`, `--rules`, `--report-new-since`, `--quiet`, `--verbose`, `--timings`, from the
  shared option groups (ADR-0019).
- Renamed, with the old spelling accepted until wave 3 and printing a note: `--include` → `--include-regions`,
  `--exclude` → `--exclude-regions`, `--experimental-embedding-rank` → `--experimental-embeddings rank`.
- Removed: none.

## Exit codes

- An unwritable baseline exits 74; before, 78. The rest of ADR-0018's table was already arcleak's.

## Report

- Added, optional for a reader (ADR-0017): `tool`, `version`, `runNotes` (`{code, severity, message, count, paths}`), `skippedFiles` (`{path, reason}`, the reason one of `notIndexed`, `changedSinceBuild`, `unreadable`, `degraded`), and `timings` with `--timings`.
- Nothing removed or retyped; `schemaVersion` stays 1. SARIF, baselines and fingerprints are byte-identical.
- With an index store: `runNotes` says "index active for N of M files; K not in the index, J changed since the build",
  and `skippedFiles` lists those files.

## Configuration

- The shared `.swift-analyzers.json` (top-level shared keys, one section per tool) is read beside the tool's own file, found from a subdirectory too, nearest first (ADR-0021).
- A configuration with an unknown or repeated key now exits 78; before, it was ignored.
- `exclude` follows ADR-0008: a glob matched against the path relative to the configuration's directory.

## Cache

`--cache-path` names a root directory now (ADR-0011): facts sit in sharded files under `<root>/facts/<workspace>/`, keyed by file metadata then content, and memory-mapped. Payloads are protobuf. A tool keeps 512 MiB at most and evicts the least recently used workspaces first. A v1 cache file at the same path is replaced. The default root is `~/Library/Caches/<tool>` on macOS and `$XDG_CACHE_HOME/<tool>` (or `~/.cache/<tool>`) on Linux. On a CI runner, delete the old v1 cache files once; the tool would replace them anyway.
The index database is under the cache root too. arcleak no longer creates `IndexDatabase/` beside a store, and old
ones can be deleted.

## Findings that may appear

- With `--index-store-path` only: findings that use the index in files the store still covers, when other files
  changed since the build. Before, a partly stale store was refused for the whole run (analyzerkit 0023, A1).
- `--only-from` with a CRLF or CR file: the findings it names. Before, such a file scoped every finding out
  (analyzerkit 0057).
- Findings in a file nested deeper than the recursion limit, now analysed on a large stack, or listed in
  `skippedFiles` as `degraded` (analyzerkit 0041).

## Findings that may disappear

- With `--index-store-path` only: a class-ness or ownership fact taken from a type definition in a file changed since
  the build. Each definition is checked for freshness now, and every definition of a name is gathered, not the first
  (0023, A3/A4).
